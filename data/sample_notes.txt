Operating Systems (CS-401): Main Memory & Virtual Memory Management

1. Memory Hierarchy & Physical Addressing:
Main memory and registers built into the processor itself are the only general-purpose storage that the CPU can access directly. Memory references are protected by the hardware base register (which holds the smallest legal physical memory address) and the limit register (which specifies the size of the range). Any attempt by user programs to access memory outside this range generates a hardware fault trapped to the operating system.

2. Paging System Architecture:
Paging avoids external fragmentation and the associated problem of compaction. Physical memory is partitioned into fixed-sized blocks known as Frames. Logical address space is partitioned into blocks of identical size known as Pages.
The logical address generated by the CPU is divided into:
- Page Number (p): Indexes the page table which contains the physical frame base address.
- Page Offset (d): Combined with base address to define the physical memory location.
If page size is 2^d bytes, the lower d bits specify the offset, and the remaining m-d bits represent the page number.

3. Translation Lookaside Buffer (TLB):
Because a page table access requires accessing physical RAM, standard paging doubles memory access time. To accelerate translation, modern CPUs use a hardware Translation Lookaside Buffer (TLB), an associative cache.
- Effective Memory Access Time (EMAT):
  EMAT = α * (t_TLB + t_mem) + (1 - α) * (t_TLB + 2 * t_mem)
  where α is the TLB hit ratio.

4. Page Replacement Algorithms:
When all frames are full and a new page is referenced:
- FIFO (First-In-First-Out): Replaces oldest page. Exhibits Belady's Anomaly (more frames can produce more page faults).
- Optimal (OPT): Replaces page that will not be used for longest future period. Minimum possible fault rate.
- LRU (Least Recently Used): Replaces page unused for longest past duration. Stack algorithm, immune to Belady's Anomaly.

5. Thrashing:
Thrashing occurs when total memory demand of active processes exceeds physical RAM capacity. The operating system spends more time swapping pages to/from disk than executing instructions, causing CPU utilization to plummet. Controlled via Working Set Model.
